# Установка Linux Lab

## Поддерживаемая среда

Текущий установочный сценарий ориентирован на Debian 12+ и Debian-подобные системы с `apt`. Базовый путь использования — интерактивная shell-сессия по SSH или локальный терминал обычного пользователя.

## Что делает `install.sh`

Скрипт:

1. Проверяет, что запуск идет на Linux.
2. Проверяет наличие структуры репозитория рядом со скриптом.
3. При наличии `apt` пытается установить базовые пакеты, которые полезны для Linux Lab.
4. Копирует `linux-lab/` в `~/linux-lab`.
5. Устанавливает `shell/lab-welcome` в `~/.local/bin/lab-welcome`.
6. Устанавливает `shell/linux-lab.sh` в `~/.local/share/linux-lab/linux-lab.sh`.
7. Один раз добавляет в `~/.bashrc` блок подключения helper-файла.

## Как запустить

```bash
git clone <repo-url> linux-lab-repo
cd linux-lab-repo
bash install.sh
exec bash
```

Если вы входите на машину по SSH, после новой сессии сработает приветственный экран Linux Lab.

## Какие файлы появляются у пользователя

- `~/linux-lab/` — учебный полигон
- `~/.local/bin/lab-welcome` — welcome-скрипт
- `~/.local/share/linux-lab/linux-lab.sh` — shell helper-функции
- блок в `~/.bashrc`, который подключает Linux Lab helper-файл

## Идемпотентность

`install.sh` можно запускать повторно. Скрипт:

- пересинхронизирует содержимое `~/linux-lab`
- перезапишет репозиторные shell-файлы актуальной версией
- не будет дублировать блок подключения в `.bashrc`

## Ограничения текущей версии

- Скрипт не создает отдельных учебных пользователей.
- Скрипт не поднимает web-terminal и не настраивает внешний SSH provisioning.
- Если у пользователя нет прав на `sudo`, пакетная часть может быть пропущена, но копирование файлов все равно продолжится.
