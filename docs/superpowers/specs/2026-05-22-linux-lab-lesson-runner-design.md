# Linux Lab Lesson Runner Design

Дата: 2026-05-22
Тема: интерактивный runner для уроков Linux Lab

## Цель

Добавить в Linux Lab интерактивный учебный режим, который ведет ученика по теме пошагово, не заменяя существующие `lesson.md`, `practice.md` и `checks.md`.

Runner должен:

- показывать контекст и текущую задачу без необходимости листать консоль;
- давать подсказки, краткую помощь и расширенное объяснение;
- проверять не только результат, но и учебную ценность введенной команды;
- оставаться content-first и редактируемым через текстовые файлы внутри темы.

## Основное решение

Выбран вариант с общим движком runner и отдельным файлом сценария внутри папки темы.

Это значит:

- логика интерфейса, переходов и проверки живет в одном общем shell-движке;
- каждая тема получает отдельный текстовый файл сценария рядом с уроком;
- автор урока может править текст, шаги, подсказки и правила без изменения самого движка.

## Принципы

- текущие уроки остаются source of truth;
- runner не отменяет обычный shell-режим, а добавляет поверх него учебный слой;
- сценарии должны быть простыми для редактирования;
- шаги должны быть понятны новичку;
- проверка должна быть гибридной: и по результату, и по ожидаемой учебной команде.

## Структура файлов

### Общий движок

В `shell/` добавляется общий runner, например:

- `shell/lesson`
- при необходимости вспомогательный файл с общей логикой

### Сценарий темы

Внутри каждой темы добавляется отдельный файл сценария, например:

- `linux-lab/tasks/01-files/runner.txt`

или другой простой текстовый формат, который:

- читается shell-движком;
- удобно редактируется вручную;
- не требует сложного синтаксиса;
- можно сопровождать вместе с `lesson.md` и `practice.md`.

## Требования к сценарию темы

Сценарий должен позволять описать:

- заголовок темы;
- краткий контекст перед началом;
- список базовых команд темы;
- шаги;
- текст задания;
- краткую подсказку;
- расширенное объяснение;
- ожидаемую категорию команды;
- способ проверки результата;
- допустимые альтернативы, если шаг это разрешает.

## Поведение runner

Runner запускается как отдельная команда и как пункт стартового меню.

### Варианты запуска

- прямая команда, например `lesson 01-files`
- запуск через `menu`

### Экран шага

На каждом шаге runner показывает:

- тему;
- текущий шаг;
- краткий контекст;
- текст задания;
- список доступных действий.

### Доступные действия

Минимально:

- ввести команду;
- `hint` — краткий намек;
- `help` — краткая справка по теме или нужной команде;
- `explain` — более подробный разбор;
- `check` — проверить текущее состояние;
- `skip` — пропустить шаг;
- `quit` — выйти из runner.

## Модель проверки

Выбран гибридный режим.

### Ранние шаги

На ранних шагах runner должен мягко подталкивать к нужной команде.

Например:

- если шаг про `find`, runner не должен засчитывать решение, полностью обходящее `find`, если это учебно важный момент;
- если результат почти верный, но команда не та, runner должен объяснить, почему шаг пока не засчитан.

### Поздние шаги

На более поздних шагах runner должен принимать альтернативные корректные решения, если итоговый результат соответствует задаче.

Это позволяет:

- сначала тренировать конкретную команду;
- потом поощрять самостоятельность и вариативность решений.

### Что именно проверяется

Runner должен уметь проверять:

- использовалась ли ожидаемая команда или группа команд;
- достигнут ли нужный результат в файловой системе или окружении;
- не была ли задача пройдена случайно или обходным нерелевантным способом.

## Взаимодействие с shell

Runner не должен подменять собой настоящий терминал.

Правильная модель:

- ученик видит задание и справку в runner;
- затем вводит команду;
- runner анализирует ввод и состояние;
- дает понятную обратную связь.

Если возможно, runner должен оставаться легким и совместимым с обычным SSH-терминалом без тяжелого TUI.

## Роль существующих файлов урока

Существующие файлы сохраняют свои роли:

- `lesson.md` — материал и объяснение;
- `practice.md` — задания;
- `checks.md` — самопроверка;
- `setup.sh` — подготовка среды;
- `verify.sh` — итоговая проверка темы.

Runner не заменяет их, а использует как учебный интерфейс поверх темы.

## Требования к UX

- новичку должно быть понятно, где он находится и что от него требуется;
- не нужно листать консоль назад в поисках задачи;
- подсказки должны быть полезными, но не выдавать решение сразу;
- runner должен различать краткую подсказку и подробное объяснение;
- текст должен быть на русском;
- работа должна быть удобна в обычной SSH-сессии.

## Требования к редактируемости

Сценарий темы должен быть понятен человеку, который умеет редактировать текст, но не хочет лезть в код движка.

Это ключевое требование для публичного репозитория:

- любой желающий должен иметь возможность открыть файл темы;
- поправить формулировку шага;
- усилить подсказку;
- скорректировать контекст;
- добавить разрешенную альтернативу;
- и сразу получить интеграцию этого текста в runner.

## Безопасные границы первой версии

В первую версию runner стоит включить:

- общий движок;
- запуск через команду и через `menu`;
- сценарий хотя бы для одной темы, например `01-files`;
- гибридную проверку на нескольких типовых шагах;
- локальные подсказки и объяснения;
- простой текстовый формат сценария.

## Что можно отложить

Не обязательно делать в первой версии:

- полноэкранный TUI;
- сохранение прогресса между сессиями;
- сложный парсинг shell-истории;
- поддержку всех тем сразу;
- продвинутую аналитику по ошибкам ученика.

## Риски и их снижение

Риск:
- runner станет слишком сложным и перестанет быть shell-first
Снижение:
- держать интерфейс простым, текстовым и совместимым с SSH

Риск:
- сценарии будет трудно редактировать
Снижение:
- выбрать максимально простой текстовый формат

Риск:
- проверка будет наказывать за альтернативные корректные решения
Снижение:
- использовать гибридную модель: сначала тренировка нужной команды, потом допуск альтернатив

Риск:
- контент урока и runner начнут расходиться
Снижение:
- хранить сценарий рядом с темой и считать основные markdown-файлы первичным учебным содержанием

## Ожидаемый результат

После реализации Linux Lab получит дополнительный режим обучения:

- ученик сможет запускать тему как пошаговую программу;
- авторы уроков смогут развивать сценарии через текстовые файлы;
- репозиторий сохранит content-first структуру;
- новичкам станет проще учиться без постоянного переключения между задачей, справкой и терминалом.
