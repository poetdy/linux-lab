# VM Reset User Script Design

## Goal

Добавить в репозиторий административный скрипт, который приводит Debian VM в состояние, близкое к "свежему пользователю", без переустановки ОС: удаляет выбранного пользователя вместе с его домашним каталогом и пересоздает пользователя с тем же именем как обычного рабочего пользователя, пригодного для прохождения Linux Lab.

## Scope

Скрипт покрывает только пользовательский reset.

В scope:
- удаление существующего пользователя и его home
- завершение процессов пользователя перед удалением
- пересоздание пользователя с `/bin/bash`
- добавление пользователя в рабочие группы Debian, включая `sudo`
- интерактивная установка нового пароля через `passwd`
- dry-run режим
- явные предохранители от случайного запуска

Вне scope:
- откат системных пакетов
- очистка всей ОС до заводского состояния
- восстановление ssh-ключей, dotfiles, history или приложений пользователя
- автоматическая установка Linux Lab после reset

## Target Location

Скрипт будет добавлен в `shell/admin/reset-user.sh`.

## Interface

Скрипт запускается только от `root`.

Поддерживаемые аргументы:
- `--user <name>`: обязательное имя пользователя для reset
- `--groups <csv>`: необязательный список secondary groups; по умолчанию используется безопасный рабочий набор для Debian VM
- `--dry-run`: показать план действий без изменений
- `--yes-reset-user`: обязательный флаг подтверждения для реального запуска
- `--help`: краткая справка

Минимальный рабочий пример:

```bash
sudo bash shell/admin/reset-user.sh --user poet --yes-reset-user
```

Проверочный прогон:

```bash
sudo bash shell/admin/reset-user.sh --user poet --dry-run
```

## Default User Profile

Пересозданный пользователь получает:
- primary group с тем же именем пользователя
- shell `/bin/bash`
- домашний каталог `/home/<user>`
- secondary groups по умолчанию: `sudo,adm,cdrom,floppy,audio,dip,video,plugdev,users,netdev`

Этот профиль выбран как "обычный рабочий пользователь Debian", который сможет проходить Linux Lab и при этом не будет избыточно кастомизирован.

## Safety Rules

Скрипт обязан прекращать работу с ошибкой, если:
- он запущен не от `root`
- не передан `--user`
- не передан `--yes-reset-user` и одновременно не включен `--dry-run`
- целевой пользователь равен текущему эффективному пользователю
- целевой пользователь равен `root`
- домашний каталог пользователя разрешается не в `/home/<user>`
- не удается безопасно завершить процессы пользователя перед удалением

Скрипт должен:
- печатать понятный план действий перед destructive шагами
- использовать `deluser --remove-home` или безопасный системный fallback
- создавать `.ssh` только как пустой каталог с корректными правами, без ключей
- не хранить пароль в аргументах, переменных окружения или файлах

## Execution Flow

1. Разобрать аргументы и провалидировать обязательные флаги.
2. Проверить, что запуск идет от `root`.
3. Определить существование пользователя и его home.
4. Проверить защитные условия.
5. Напечатать итоговый план изменений.
6. Если включен `--dry-run`, завершиться без изменений.
7. Завершить процессы пользователя.
8. Удалить пользователя и его home.
9. Создать пользователя заново с `/bin/bash`.
10. Назначить secondary groups.
11. Создать `~/.ssh` и выставить владельца и права.
12. Интерактивно вызвать `passwd <user>`.
13. Напечатать итоговую сводку и базовые команды проверки.

## Errors and Recovery

Если удаление прошло, а пересоздание сорвалось, скрипт должен завершиться с явным сообщением, что пользователь удален частично и требует ручного восстановления. Скрипт не должен пытаться "магически" восстанавливать состояние без явного контроля администратора.

Если одной из secondary groups нет в системе, скрипт должен:
- по умолчанию пропустить отсутствующую группу
- вывести предупреждение, какие группы не были назначены

Это делает скрипт переносимым между Debian-подобными VM с немного разным набором групп.

## Verification

Минимальная проверка после успешного запуска:

```bash
id <user>
getent passwd <user>
ls -ld /home/<user> /home/<user>/.ssh
```

Ожидаемое состояние:
- пользователь существует
- shell равен `/bin/bash`
- пользователь состоит в `sudo`
- домашний каталог создан заново
- `.ssh` пустой и имеет безопасные права

## Open Decisions Resolved

- Пароль задается интерактивно через `passwd`
- Пользователь должен быть обычным рабочим пользователем для Linux Lab
- Пользователь должен входить в `sudo`
