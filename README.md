# Linux Lab

Linux Lab — это публичный content-first монорепозиторий с практическим полигоном по Linux. В центре проекта находится не деплой сам по себе, а учебное содержимое: темы, упражнения, проверки, shell-подсказки и сценарии, которые помогают руками наработать уверенность в терминале.

Проект рассчитан на тех, кто хочет последовательно пройти путь от базовой навигации по файловой системе до диагностики процессов, сети, логов, SSH, Bash и Docker. Репозиторий устроен так, чтобы его можно было и установить на Debian-машину, и развивать как открытый набор учебных материалов, где shell-слой обслуживает контент, а не наоборот.

## Что внутри

- `linux-lab/` — основной учебный контент, который разворачивается у пользователя в `~/linux-lab`
- `shell/` — shell-слой: welcome-скрипт, helper-функции, многоуровневая справка, команда `menu` и lesson runner
- `docs/` — документация для сопровождающих и контрибьюторов
- `install.sh` — установка Linux Lab на Debian

## Темы Linux Lab

```text
01-files        файлы и директории
02-permissions  права доступа
03-processes    процессы и базовая работа со службами
04-network      адреса, порты и доступность сервисов
05-logs         чтение и фильтрация логов
06-ssh          ключи, config и типовые ошибки доступа
07-bash         пайпы, grep, sed, awk и обработка вывода
08-docker       базовые сценарии Docker и диагностика контейнеров
```

Внутри каждой темы ожидается единый набор файлов:

- `lesson.md`
- `practice.md`
- `checks.md`
- `setup.sh`
- `verify.sh`

`setup.sh` используется для подготовки среды там, где тема требует артефактов для практики. В темах с интерактивным сопровождением рядом может лежать `runner.txt`.

## Установка

Минимальный путь установки на Debian:

```bash
git clone https://github.com/poetdy/linux-lab.git linux-lab-repo
cd linux-lab-repo
bash install.sh
exec bash
```

После установки Linux Lab появится в `~/linux-lab`, а shell-помощники станут доступны в новой сессии. Если вы подключаетесь по SSH, приветственный экран покажет, с чего начать.

Подробности по установке: [docs/install.md](docs/install.md)

После установки справка работает в несколько слоев:

- `h` сначала пробует `tldr --language ru`, затем обычный `tldr`;
- `hman` пробует `man` с `LANG=ru_RU.UTF-8`;
- `hs` ищет по системным `man`-описаниям и по локальным help-файлам;
- если системного покрытия не хватает, Linux Lab показывает локальную офлайн-подсказку из репозитория.

Эту же многоуровневую цепочку справки использует и lesson runner, когда внутри шага вызывается `help`.

## Как проходить обучение

Есть два нормальных режима прохождения темы.

Стандартный путь: откройте [linux-lab/README.md](linux-lab/README.md), перейдите в нужную тему, прочитайте `lesson.md`, затем выполните практику из `practice.md`, при необходимости предварительно запустив `setup.sh`, и проверьте себя через `checks.md` и `verify.sh`.

Интерактивный путь: запустите `lesson 01-files`, чтобы пройти тему пошагово внутри shell. Сейчас runner реализован как минимум для `linux-lab/tasks/01-files/runner.txt`: он показывает задание, при необходимости сам подготавливает среду урока, переводит в рабочий каталог темы и дополнительно понимает `hint`, `help`, `explain`, `check`, `skip` и `quit`.

На ранних шагах runner может мягко настаивать на нужной команде, а на поздних больше ориентироваться на корректный результат.

`menu` не заменяет `lesson`, а связывает с ним навигацию: из меню можно открыть README учебного полигона, увидеть список тем, перейти в `01-files` или запустить `lesson` для темы, где уже есть `runner.txt`.

Рекомендуемый маршрут:

`01-files` → `02-permissions` → `03-processes` → `04-network` → `05-logs` → `06-ssh` → `07-bash` → `08-docker`

## Как участвовать в развитии

Linux Lab задуман как content-first репозиторий, поэтому основная зона улучшений — сами уроки, практические сценарии, проверки и связанные с ними runner-сценарии.

- Хотите поправить или усилить конкретную тему: редактируйте файлы в `linux-lab/tasks/<topic>/`
- Хотите изменить требования к структуре тем: начните с [docs/content-guide.md](docs/content-guide.md)
- Хотите предложить изменения по установке и shell-слою: смотрите `install.sh` и файлы в `shell/`

Общие правила контрибьюта описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

Для обслуживания VM перед повторной установкой Linux Lab в репозитории есть админ-утилита [shell/admin/reset-user.sh](shell/admin/reset-user.sh), которая может пересоздать рабочего пользователя в почти "свежем" состоянии.

## Честно о текущем состоянии

Это первая публичная базовая версия монорепозитория. В ней уже есть актуальный учебный контент, shell-слой онбординга, shell-помощники и Debian-установщик, но более широкий контур еще впереди:

- автоматизация SSH-provisioning
- web-terminal режим
- временные учебные пользователи
- автоматический reset учебной среды
