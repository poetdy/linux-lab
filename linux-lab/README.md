# Linux Lab

Добро пожаловать в Linux Lab.

Это основной учебный контент публичного content-first репозитория Linux Lab. Здесь можно спокойно и последовательно прокачивать навыки работы с Linux: от базовых команд и прав доступа до логов, SSH, сетевой диагностики и Docker.

Здесь не нужно бояться ошибок. Лаборатория специально сделана так, чтобы ты мог тренироваться руками, повторять команды, ломать учебные сценарии и собирать их обратно. Главная цель — не просто прочитать материал, а начать уверенно действовать в терминале.

Shell-слой Linux Lab живет отдельно и помогает работать с этим контентом: показывает welcome-экран, добавляет многоуровневую справку, дает `menu` и умеет запускать интерактивные уроки через `lesson <topic>`.

## Главное правило

Перед опасными экспериментами — snapshot.

Если собираешься делать что-то, что может затронуть систему шире, чем учебный каталог `~/linux-lab`, сначала зафиксируй текущее состояние.

## Как проходить обучение

У темы есть два обычных режима прохождения: стандартный markdown-путь и интерактивный runner там, где он уже реализован.

### Стандартный режим

Для каждой темы используй один и тот же ритм:

1. Зайди в нужную директорию внутри `tasks/`.
2. Прочитай `lesson.md` и обрати внимание на команды и примеры.
3. Запусти `setup.sh`, чтобы подготовить среду для практики.
4. Выполни задания из `practice.md` руками, без копирования больших готовых решений.
5. Сверься с `checks.md` и проверь, все ли признаки результата на месте.
6. Запусти `verify.sh`, чтобы получить автоматическую проверку.
7. Если что-то не сошлось — исправь и пройди упражнение еще раз.

Пример:

```bash
cd ~/linux-lab/tasks/01-files
bash setup.sh
sed -n '1,200p' lesson.md
sed -n '1,240p' practice.md
bash verify.sh
```

### Интерактивный режим

Если для темы есть `runner.txt`, можно идти пошагово прямо внутри shell:

```bash
lesson 01-files
```

Сейчас такой runner реализован как минимум для `01-files` через `linux-lab/tasks/01-files/runner.txt`.

Интерактивный runner умеет:

- при необходимости сам запускает `setup.sh`;
- переводит тебя в рабочий каталог темы;
- показывает шаг, контекст и учебный фокус;
- понимает встроенные действия `hint`, `help`, `explain`, `check`, `skip`, `quit`;
- на ранних шагах чаще проверяет нужную команду, а на поздних сильнее смотрит на результат.

Команда `menu` связана с этим режимом напрямую: из меню можно открыть README, увидеть список тем, перейти в `01-files` или запустить `lesson` для темы, где уже есть runner.

## Как учиться эффективнее

- Печатай команды руками. Так навык закрепляется намного лучше.
- Не спеши переходить дальше, если текущая тема еще не стала понятной на практике.
- Если команда не сработала, не пропускай ошибку — попробуй понять, что именно пошло не так.
- Повторяй упражнения несколько раз, пока не начнешь вспоминать команды без подсказки.
- Пробуй свои варианты решения, если они остаются внутри `~/linux-lab`.
- Если тема дается тяжело, разбивай работу на маленькие шаги: сначала понять, потом повторить, потом сделать без подсказки.

## Что есть в каждой теме

Обычно внутри темы лежат такие файлы:

- `lesson.md` — короткий урок и основные команды
- `practice.md` — практические задания и мини-кейсы
- `checks.md` — самопроверка и контрольные вопросы
- `setup.sh` — подготовка учебной среды, если тема требует артефактов для практики
- `verify.sh` — автоматическая проверка результата

В темах с интерактивным режимом дополнительно может лежать `runner.txt`. Он не заменяет `lesson.md` и `practice.md`, а добавляет поверх них пошаговую оболочку для `lesson <topic>`.

## Команды помощи

```text
h команда       # краткая справка
hman команда    # русская man-страница
hs слово        # поиск по man
lab             # список тем
menu            # навигация по Linux Lab и запуск lesson runner
```

Справка работает в несколько слоев:

1. `h` сначала пытается показать русскую короткую подсказку через `tldr`, затем обычный `tldr`.
2. `hman` пытается открыть `man` с русской локалью.
3. `hs` ищет и по системным описаниям, и по локальным help-файлам Linux Lab.
4. Если системной справки не хватает, Linux Lab использует локальный fallback из help-файлов.

Эту же цепочку использует lesson runner, если внутри шага ввести `help`.

## Темы

```text
01-files        файлы и директории
02-permissions  права доступа
03-processes    процессы, сигналы, базовая работа со службами
04-network      адреса, порты, доступность сервисов
05-logs         чтение и фильтрация логов
06-ssh          ключи, config, типовые ошибки доступа
07-bash         пайпы, grep, sed, awk, обработка вывода
08-docker       базовые сценарии Docker и диагностика контейнеров
```

## Рекомендуемый маршрут

Если проходишь полигон впервые, иди по порядку:

`01-files` → `02-permissions` → `03-processes` → `04-network` → `05-logs` → `06-ssh` → `07-bash` → `08-docker`

Так темы будут опираться друг на друга, и практика станет заметно понятнее.

## Важная мысль

Не цель пройти все быстро.

Цель — дойти до состояния, когда ты:
- узнаешь типовые команды без шпаргалки,
- понимаешь, что именно проверяешь,
- можешь повторить решение еще раз с нуля,
- и не теряешься, если что-то пошло не так.

Если хочешь, веди свои заметки по каждой теме прямо в `notes/` и фиксируй команды, которые хочется запомнить отдельно.
